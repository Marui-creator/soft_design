# SVG 命令行编辑器实验

## 架构方案

### 模块划分

- cli：读取命令、解析参数、输出结果。
- commands：封装命令，管理撤销与重做。
- model：管理画布、图形和容器，提供统一操作。
- infrastructure：读取和保存 SVG 文件。

### 设计模式

- Command：每条编辑命令作为一个撤销、重做单元。
- Composite：容器和普通图形通过统一接口操作。

### 依赖方向

- cli 可以依赖 commands。
- commands 可以依赖 model。
- infrastructure 可以依赖 model。
- model 不依赖命令行和文件读写模块。
- 程序入口负责组装各模块。

### 变化点假设

- 后续可能增加图形类型。
- 后续可能增加图形界面。
- 后续可能更换文件读写方式。
- 具体扩展方式随实现补充。

## 过程记录

以下记录根据 Git 提交历史和实际操作补记。

### 1. 开发环境与项目初始化

配置 TypeScript、tsx 和 Node.js 类型定义，添加 cli、
typecheck、build 脚本，并通过 .gitignore 忽略依赖和编译产物。

配置过程中曾将 tsconfig.json 放进 node_modules。
发现后将它移至项目根目录，并重新运行类型检查和编译，
确认根目录配置能够被正确读取。

### 2. 命令行入口

实现 CliApplication，由 main.ts 创建并启动。
支持提示符、help、跳过空行和注释，以及未知命令错误提示。

运行时曾仍然输出初始化测试文字。检查发现 main.ts
尚未调用 CliApplication，修改入口并保存后，能够正常进入 svg>。

出现过编辑器提示无法识别 Node.js 模块、但命令行类型检查
通过的情况。检查了类型依赖和 tsconfig.json，并排查编辑器
TypeScript 服务与项目配置。

### 3. 画布模型与文档命令

实现 SvgDocument、EditorSession 和 Command 接口，
通过命令表接入 init、canvas。

尺寸由 SvgDocument 封装，修改前先校验全部参数。
手动验证了默认尺寸、尺寸修改、未初始化时的错误提示，
以及非法尺寸和非数字参数的拒绝。

非法 resize 和 init 执行后，原画布仍保持 400×300，
确认失败没有破坏已有文档。

### 4. 矩形创建与属性查看

实现 Shape 抽象基类、Rect 子类和 ShapeFactory，
在文档中通过 Map 保存 ID 与图形的对应关系。

接入 create rect 和 show，验证了创建、属性显示、
重复 ID 拒绝，以及不存在的 ID 错误提示。
非法矩形创建失败后，相同 ID 仍可用于合法创建。

show 通过调用图形的 describe 方法显示属性，
没有在显示命令中按图形类型分派。

### 5. 移动与缩放

接入 move、scale，通过 Shape 的统一方法操作图形。

验证了移动只改变位置，缩放同时改变位置和尺寸。
对零缩放倍数和非数字位移参数进行检查，
确认操作失败后矩形属性不变。

### 6. 撤销与重做

为图形和文档增加 clone 方法，通过独立副本保存历史状态。
CommandHistory 管理撤销栈与重做栈，
HistoryEditCommand 将已有编辑命令接入历史管理。

验证了撤销后执行新编辑会清空重做记录。
查看画布尺寸不影响历史，修改尺寸后禁止撤销，
符合实验文档第 4.3 节的规定。

当前成功提示仍较简略，后续需要完善。

### 7. 矩形属性修改

通过 setAttribute 统一接口接入 set 命令，
支持矩形几何属性及 fill、stroke、stroke-width。
同步更新 clone，确保新增属性能随历史快照恢复。

验证了属性修改、撤销重做，以及非法宽度和未知属性的拒绝。
非法修改后，原图形属性保持不变。

### 8. 补齐基本图形

增加 Circle、Ellipse、Line、Text，均继承 Shape，
实现移动、缩放、属性修改、显示和复制方法。
通过 ShapeFactory 根据类型名创建对象。

已有命令通过 Shape 接口操作图形，因此新增类型时，
无需修改移动、缩放、删除和查看命令。

通过 CLI 验证各类型的基本操作、属性修改及撤销重做。
非法半径和非数字参数被拒绝，失败后原图形属性保持不变。

### 9. 双引号参数解析与文字内容

原先通过空白拆分命令，无法处理带空格的文字。
新增 CommandParser，逐字符解析输入，
保留双引号内的空格，并支持空字符串参数。

验证了带空格英文、中文、空文本及内容修改的撤销重做。
未闭合引号会报错，不改变文档状态。
当前尚不支持双引号转义。

### 10. 阶段性待处理项

- 图形之间存在重复的样式处理和数值解析代码，需要整理。
- 命令分发和图形工厂的按名分派按实验要求记录为待重构项。
- 成功提示和帮助文本需要随最终功能统一完善。
- 容器、分组、图层顺序、tree 和 SVG 读写尚未实现。

### 11. 容器与层级操作

新增 Group，容器和叶子图形共同继承 Shape。
容器通过递归调用子图形的方法，实现整体移动、缩放和深复制。

文档保存根级图形，容器保存直接子图形。
通过递归查找定位任意层级的 ID，并检查全文档 ID 唯一性。

实现 create g、创建时指定 in、tree、addto、
group、ungroup、front 和 back。

手动验证了嵌套创建、父级显示、容器整体移动、
删除容器及撤销恢复、移动归属、分组和解组。
解组后子图形占据原容器位置，保持顺序。
验证了循环嵌套拒绝、根级容器解组拒绝，
以及同级图层调整和撤销重做。

当前待检查：

- 带样式容器解组后对图形外观的影响。
- 文字参数与 in 子句的解析歧义。
- tree 对 describe 输出格式的依赖。

### 12. SVG 文件读写

通过 DocumentReader、DocumentWriter 接口隔离文件读写，
基础设施层负责 XML 解析和文件访问。

保存时通过 SvgElement 生成 XML，对属性和文字内容转义。
读取时先构建新文档，成功后才替换当前文档。
先扫描已有 ID，再为缺失 ID 的元素补名并返回警告。

验证了缺失 ID 补全、已有 ID 避让、嵌套结构恢复、
中文和特殊字符的读写，并在浏览器检查保存结果。

当前导入范围有限：尚不支持 transform，
viewBox 只接受原点为零且与画布尺寸一致的形式，
额外 SVG 属性和 CSS 的处理仍需完善。

## 一致性自查

### 模块划分

目前已有 src/cli、src/commands、src/model，
基本对应初版模块方案。
infrastructure 尚未建立，SVG 文件读写尚未实现。

Shape 已提供统一操作接口，但容器类型和父子关系尚未实现，
因此 Composite 目前仍是架构目标。

### 依赖方向

根据当前实现，commands 依赖 model，model 不依赖 CLI 和文件读写。

CliApplication 除依赖 commands 外，还直接依赖 ShapeFactory，
并负责创建会话、历史管理器和命令对象。
这超出了初版“cli 可以依赖 commands”的规则，
属于当前待处理项，后续计划将对象组装移至程序入口。

以上为阶段性检查，后续仍需结合实际 import 关系复查。

## 质量保证手段

各阶段运行 npm run typecheck 和 npm run build，
检查类型与编译问题。

通过 CLI 手动验证：

- 默认画布、尺寸修改和非法尺寸拒绝。
- 图形创建、重复 ID 检查和不存在的 ID 提示。
- 五种基本图形的移动、缩放、属性查看和修改。
- 编辑操作的撤销重做，以及新编辑清空重做记录。
- 查看尺寸不影响历史，修改尺寸后禁止撤销重做。
- 双引号参数、空文本和未闭合引号的处理。
- 非法编辑失败后，图形属性保持不变。

目前以手动验证为主，尚未建立自动化测试，
也尚未完成 SVG 文件读写和浏览器预览验证。
这些检查不能代表全部实验要求已经满足。
