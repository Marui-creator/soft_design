# SVG 命令行编辑器实验

## 架构方案

### 模块划分
- cli：读取命令、解析参数、输出结果。
- commands：封装命令，管理撤销与重做。
- model：管理画布、图形和容器，提供统一操作。
- infrastructure：读取和保存 SVG 文件。

### 设计模式
- Command：每条编辑命令作为一个撤销、重做单元。
- Composite：容器和普通图形通过统一接口操作。

### 依赖方向
- cli 可以依赖 commands。
- commands 可以依赖 model。
- infrastructure 可以依赖 model。
- model 不依赖命令行和文件读写模块。
- 程序入口负责组装各模块。

### 变化点假设
- 后续可能增加图形类型。
- 后续可能增加图形界面。
- 后续可能更换文件读写方式。
- 具体扩展方式随实现补充。

## 过程记录

以下记录根据 Git 提交历史和实际操作补记。

### 1. 开发环境与项目初始化

配置 TypeScript、tsx 和 Node.js 类型定义，添加 cli、
typecheck、build 脚本，并通过 .gitignore 忽略依赖和编译产物。

配置过程中曾将 tsconfig.json 放进 node_modules。
发现后将它移至项目根目录，并重新运行类型检查和编译，
确认根目录配置能够被正确读取。

### 2. 命令行入口

实现 CliApplication，由 main.ts 创建并启动。
支持提示符、help、跳过空行和注释，以及未知命令错误提示。

运行时曾仍然输出初始化测试文字。检查发现 main.ts
尚未调用 CliApplication，修改入口并保存后，能够正常进入 svg>。

出现过编辑器提示无法识别 Node.js 模块、但命令行类型检查
通过的情况。检查了类型依赖和 tsconfig.json，并排查编辑器
TypeScript 服务与项目配置。

### 3. 画布模型与文档命令

实现 SvgDocument、EditorSession 和 Command 接口，
通过命令表接入 init、canvas。

尺寸由 SvgDocument 封装，修改前先校验全部参数。
手动验证了默认尺寸、尺寸修改、未初始化时的错误提示，
以及非法尺寸和非数字参数的拒绝。

非法 resize 和 init 执行后，原画布仍保持 400×300，
确认失败没有破坏已有文档。

### 4. 矩形创建与属性查看

实现 Shape 抽象基类、Rect 子类和 ShapeFactory，
在文档中通过 Map 保存 ID 与图形的对应关系。

接入 create rect 和 show，验证了创建、属性显示、
重复 ID 拒绝，以及不存在的 ID 错误提示。
非法矩形创建失败后，相同 ID 仍可用于合法创建。

show 通过调用图形的 describe 方法显示属性，
没有在显示命令中按图形类型分派。

### 5. 移动与缩放

接入 move、scale，通过 Shape 的统一方法操作图形。

验证了移动只改变位置，缩放同时改变位置和尺寸。
对零缩放倍数和非数字位移参数进行检查，
确认操作失败后矩形属性不变。

### 6. 撤销与重做

为图形和文档增加 clone 方法，通过独立副本保存历史状态。
CommandHistory 管理撤销栈与重做栈，
HistoryEditCommand 将已有编辑命令接入历史管理。

验证了撤销后执行新编辑会清空重做记录。
查看画布尺寸不影响历史，修改尺寸后禁止撤销，
符合实验文档第 4.3 节的规定。

当前成功提示仍较简略，后续需要完善。
